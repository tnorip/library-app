# 要件定義書（ドラフト）— みどり市立図書館管理システム

## 1. 背景・目的

みどり市立図書館（利用者 8 万人 / 蔵書 25 万冊）は以下の課題を抱えており、図書管理システムの導入により解決を目指す。

- 蔵書・貸出・予約管理がすべて紙の台帳による手書き運用で、業務効率が著しく低い
- 予約受付が電話・来館のみで、利用者の利便性が低く来館者数が5年間で約20%減少
- 手書き台帳では統計集計が困難で、議会への報告資料の作成に支障が出ている
- 職員全員が台帳を閲覧可能な状態で、個人情報保護の観点からリスクがある
- IT専任担当者が1名のみで、今年度中に改善案を議会へ提示しないと来年度予算が組めない

## 4. 優先度マトリクス（MoSCoW）

### Must have（必須）

#### US-003: 本の状態確認（司書）
> As a 司書（田中さん）
> I want to 本の貸出状況・所在・ステータス（貸出中／在庫／修繕中など）を即座に確認できる
> So that 利用者からの問い合わせにフロアを歩き回らずすぐ答えられる

受け入れ条件:
- [ ] タイトル・著者名・ISBNで本を検索できる
- [ ] 検索結果に貸出状況（在庫／貸出中／修繕中／廃棄予定）が表示される
- [ ] 貸出中の場合、返却予定日が確認できる
- [ ] 本の棚の場所（分類番号）が確認できる

#### US-005: 貸出・返却処理のデジタル化（司書）
> As a 司書（田中さん）
> I want to 貸出・返却をシステム上で処理できる
> So that 手書き台帳への記録がなくなり、処理速度が上がりミスも減らせる

受け入れ条件:
- [ ] 利用者アカウントと本を紐づけて貸出処理ができる
- [ ] 貸出時に上限冊数・貸出期間のルールが自動チェックされる
- [ ] 返却処理をするとステータスが「在庫」に自動更新される
- [ ] 返却時に予約待ちがあれば司書に通知される

#### US-006: 蔵書管理のデジタル化（司書）
> As a 司書（田中さん）
> I want to 本の登録・廃棄・ステータス変更（在庫／貸出中／修繕中／廃棄予定）をシステム上で管理できる
> So that 台帳への手書き作業がなくなり、蔵書状態をすぐに把握・更新できる

受け入れ条件:
- [ ] 本のタイトル・著者・ISBN・出版社・出版年・分類番号を登録できる
- [ ] 同一ISBNで複数冊を管理できる（冊ごとに個別ステータスを持つ）
- [ ] ステータスを「在庫／貸出中／修繕中／廃棄予定」に変更できる
- [ ] 廃棄処理した本はシステムから論理削除される

#### US-007: アクセス権限管理（館長）
> As a 館長（山本さん）
> I want to 職員の役職・権限レベルに応じてアクセスできる情報・操作を制限できる
> So that 利用者の個人情報が必要な職員のみに限定され、情報漏洩リスクを防げる

受け入れ条件:
- [ ] 職員に「一般職員／主任／館長」のロールを設定できる
- [ ] ロールごとにアクセスできる機能・情報が制限される
- [ ] 利用者の個人情報（貸出履歴など）は主任以上のみ閲覧できる
- [ ] 権限外の操作を試みた場合、エラーメッセージが表示される

#### US-013: 利用者アカウント管理（司書）
> As a 司書
> I want to 利用者のアカウントを登録・更新・削除できる
> So that 予約・貸出・通知などの機能を利用者ごとに紐づけて管理できる

受け入れ条件:
- [ ] 利用者の氏名・連絡先・利用者番号を登録できる
- [ ] 利用者情報を更新・退会処理できる
- [ ] 退会処理した利用者の貸出中の本がある場合、警告が表示される

#### US-014: 職員アカウント・権限管理（館長）
> As a 館長
> I want to 職員アカウントを登録し、役職に応じた権限ロールを設定できる
> So that US-007のアクセス制限が機能する土台を整えられる

受け入れ条件:
- [ ] 職員アカウントを新規登録・更新・無効化できる
- [ ] 職員にロール（一般職員／主任／館長）を割り当てられる
- [ ] 退職などで無効化した職員はログインできなくなる

#### US-015: 貸出ルール設定（館長／主任司書）
> As a 館長・主任司書
> I want to 貸出上限冊数・貸出期間などのルールをシステムに設定できる
> So that 貸出・延滞管理が正しいルールに基づいて自動で動く

受け入れ条件:
- [ ] 貸出上限冊数（デフォルト10冊）を設定できる
- [ ] 貸出期間（デフォルト2週間）を設定できる
- [ ] 設定変更は主任以上のみ操作できる

### Should have（重要）

#### US-001: オンライン予約（利用者）
> As a 図書館利用者（佐藤さん）
> I want to スマートフォンから図書の予約・キャンセル・状況確認ができる
> So that わざわざ来館しなくても予約管理ができる

#### US-002: 本の状態確認（利用者）
> As a 図書館利用者（佐藤さん）
> I want to 本のタイトルや著者名で検索し、貸出状況・棚の場所をリアルタイムで確認できる
> So that 来館前に空振りを防げ、来館後もすぐに本を見つけられる

#### US-004: 予約管理の自動化（司書）
> As a 司書（田中さん）
> I want to 利用者がオンラインで予約・キャンセルを自己完結でき、司書は予約状況の確認のみできる
> So that 電話対応による業務中断がなくなり、予約管理のミスも減らせる

#### US-008: 操作履歴・監査ログ（館長／主任司書）
> As a 館長・主任司書
> I want to 誰がいつどの操作をしたかの履歴を確認できる
> So that ミスの原因追跡ができ、不正アクセスの抑止にもなる

#### US-009: 利用統計・業務レポート（館長）
> As a 館長（山本さん）
> I want to 貸出数・来館者数・人気ジャンル等の統計を月次・週次で確認できる
> So that 議会への報告資料を効率的に作成でき、運営改善の意思決定に活用できる

#### US-010: 延滞管理・督促通知（司書）
> As a 司書（田中さん）
> I want to 返却期限を超えた利用者へ自動で通知を送れる
> So that 督促電話の精神的負担がなくなり、返却率も改善される

#### US-012: 貸出状況・返却期限の自己確認（利用者）
> As a 図書館利用者（佐藤さん）
> I want to 自分の借冊数・返却期限・予約状況をスマートフォンから確認できる
> So that 確認だけのための来館が不要になり、時間を有効に使える

### Could have（あれば良い）

#### US-011: 購入希望の受付・管理（司書）
> As a 司書（田中さん）
> I want to 利用者からの購入希望をシステムで受け付け、対応状況を管理できる
> So that 希望者への対応状況をいつでも確認・回答でき、管理漏れを防げる

### Won't have（今回のスコープ外）

- 電子書籍の管理・配信機能
- 外部図書館システムとの連携
- 新着本・レコメンドのプッシュ通知
- 利用者向けレビュー・評価機能

## 5. 制約・前提条件

| 項目 | 内容 |
|------|------|
| 個人情報保護 | 利用者の貸出履歴等はアクセス権限により厳密に管理する |
| 運用体制 | IT担当1名でも運用保守が可能なシンプルな設計とする |
| 貸出ルール | 上限10冊・貸出期間2週間（設定で変更可能） |
| スコープ | 今年度中に議会へ提示できる第一次リリースに収まる範囲とする |
| 操作性 | 専門知識がなくても直感的に操作できるシンプルなUI |
